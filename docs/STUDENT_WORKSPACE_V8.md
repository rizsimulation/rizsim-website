# Student workspace V8

## Scope
Student pages only: Home, RizSimulation Player, Practice, Simulation Library, About and Contact. My Learning is reachable from the sidebar, not a main tab or swipe destination. Account details remain accessible from sidebar/account menu as a dialog. The old catalogue and account tabs are not accessible; event-bound legacy DOM is retained hidden to avoid breaking established renderers.

The shared Home remains sourced from index.html. Only student category cards are replaced with Join a class and Simulation Library. Public and Faculty Home and all Faculty authoring/runtime files remain unchanged. A minimal student-only Home hook is the sole shared-source change.

## Practice
Practice comes from the current user's already-joined classes, not from an unrestricted faculty-session catalogue. Students first use the Faculty code/link in Player. No enrolments, licences, sessions or new attempts are generated by viewing Practice.

Countdowns use the server clock plus elapsed monotonic time. Effective expiry cannot exceed the practice window, simulation licence or purchased-course licence. Scheduled, unavailable, expired, submitted and empty states are distinct. A failed data request never produces a completion message. The list refreshes on return/visibility, on request, and every minute while visible. Launch always rechecks server authorization.

The existing platform has one attempt per user/class. Explicitly choosing practice may transition that same unsubmitted attempt from live to practice only while authorized. It does not reset answers/progress or reopen submitted work. The guarded function rejects foreign, suspended, expired, closed, revoked and submitted access.

## History and resources
History shows only recorded join/start/activity/submission dates, with search and status filters. It does not invent detailed event telemetry or scores. Simulation Library contains simulations from the student's own interactions, existing protected reading resources, and current published classroom resources. Player shows resources for the selected joined class. External resource opening revalidates access through the existing material-context function; file access remains through the existing protected viewer. Revocation cannot retract copied external URLs or previously downloaded files.

## Verification
Automated Chromium tests use isolated fixture accounts and data. Database assertions run in disposable PostgreSQL 16 with no production user data. No paid browser or TinyFish service is used. Production verification covers exact delivered files and backend definition/permission checks, not a newly signed-in live rehearsal.

## Deployment boundaries
Only two additive RPC functions; no replacement of existing resolve/join/submit/launch functions, no table creation, no role or licence grants. The existing student attempt queries now explicitly filter current user in addition to RLS. Authentication stays on the existing shared Supabase client.
